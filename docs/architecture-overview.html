📋 Projektübersicht

FoodDatabase ist eine private Lebensmittel- und Rezeptverwaltungsanwendung für das Heimnetzwerk.

🎯 Hauptziele

  • Überblick über Lebensmittel an verschiedenen Lagerorten behalten
  • Nährwerte von Rezepten automatisch berechnen
  • Verfallsdaten überwachen (gelb/rot Warnungen)
  • Einkaufslisten automatisch generieren (Mindestbestand-Trigger)
  • Verbrauchte Produkte ausbuchen (per Scan oder manuell)

📊 Technische Eckdaten

Aspekt Details
Frontend Blazor Server (ASP.NET Core 8)
Backend C# / ASP.NET Core 8
Datenbank SQLite (mit Entity Framework Core)
Deployment Docker Container auf TrueNAS
Clients Windows, iOS, Android (Browser)
Netzwerk Lokales Heimnetzwerk (LAN)
Benutzer Max. 3 gleichzeitig (keine Auth erforderlich)

🏗️ Systemarchitektur

Schichtenmodell

FoodDatabase folgt einer layered architecture:

┌─────────────────────────────┐
│   Presentation Layer        │  ← Blazor Server (WebUI)
├─────────────────────────────┤
│   Business Logic Layer      │  ← Services (CRUD, Calculations)
├─────────────────────────────┤
│   Data Access Layer         │  ← Repository Pattern
├─────────────────────────────┤
│   ORM Layer                 │  ← Entity Framework Core
├─────────────────────────────┤
│   Persistence Layer         │  ← SQLite Database
└─────────────────────────────┘

Design Patterns

  • Repository Pattern - Data access abstraction
  • Dependency Injection - Loose coupling, testability
  • Service Layer - Business logic separation
  • SOLID Principles - Clean code practices
  • Async/Await - Non-blocking operations

💻 Entwicklungs-Workflow

Agenten-Orchestrierung

Jeder Use-Case folgt diesem Workflow:

  1. Test-Agent: Schreibt 20+ Unit Tests (TDD Red)
  2. Dev-Agent: Implementiert Code (TDD Green)
  3. Review-Agent: Überprüft Code-Qualität
  4. Doc-Agent: Dokumentiert & aktualisiert Diagramme
  5. User: Reviewed lokal und gibt Approval
  6. ✅ Merge zu master
