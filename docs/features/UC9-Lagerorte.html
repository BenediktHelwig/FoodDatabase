UC9: Dynamische Lagerorte Verwaltung

Use-Case 9-Erweiterung | Status: ⏳ IN ENTWICKLUNG | Dokumentation: ✅ SPEZIFIZIERT

📋 Übersicht

Beschreibung: UC9 ist eine Erweiterung des Produktinstanzen-Systems (UC10). Statt vordefinierter Lagerorte (Enums) werden Lagerorte nun dynamisch angelegt beim Erstellen von ProduktInstanzen oder beim Buchen zu neuen Orten.

Hauptziele

  • Dynamische Lagerorte-Anlage (keine vordefinierte Liste)
  • Auto-Complete mit Fuzzy-Matching für Benutzerfreundlichkeit
  • Normalisierung von Eingaben (z.B. "lagerA" → "LagerA")
  • Persistierung in separater Lagerorte-Tabelle (SQLite)
  • Keine Löschung von Lagerorten (Audit-Trail)

Geschäftsnutzen

Der Benutzer kann beliebig viele Lagerorte anlegen, ohne dass diese vorher vom Admin definiert werden müssen. Das System schlägt bereits existierende Lagerorte vor, um Duplikate zu vermeiden. Dies ist essentiell für Lagerverwaltung in dynamischen Umgebungen (Umzüge, neue Lagerbereiche).

🔧 Technische Anforderungen (SPEZIFIZIERT)

Normalisierung & Validierung

Aspekt Anforderung Beispiel
Validierung Nur Buchstaben (A-Z, a-z). Keine Zahlen/Sonderzeichen "LagerA" ✅, "Lager1" ❌
Normalisierung Single-Word-Input: Capitalize (1. Buchstabe groß, Rest klein) "lagerA" → "LagerA", "LAGER" → "Lager"
Speicherung Case-Sensitive (wird unterschieden) "Lager" ≠ "lager" (verschiedene Einträge)
Auto-Complete Partial Prefix Matching (Case-Insensitive Input) Input "lag" findet "Lager", "LagerA", "LagerB"
Duplikat-Handling GetOrCreate: Existiert bereits? → Return existing, sonst Create Input "Lager" 2x → Only 1 Eintrag in DB
Limits Keine Limit (beliebig viele Lagerorte) User kann 100+ Lagerorte anlegen
Löschung NICHT erlaubt (Audit-Trail bleibt sauber) Gelöschte Lagerorte: → Soft-Delete mit IsArchived-Flag (optional)

📦 Database Schema (NEU)

Neue Tabelle: Lagerorte

CREATE TABLE Lagerorte (
    Id INT PRIMARY KEY AUTO_INCREMENT,
    Name VARCHAR(100) NOT NULL UNIQUE,
    CreatedAt DATETIME NOT NULL DEFAULT GETDATE(),
    IsArchived BIT NOT NULL DEFAULT 0
);

Tabelle: ProduktInstanz (UPDATED)

ALTER TABLE ProduktInstanzen
ADD COLUMN LagerortId INT NULLABLE,
ADD CONSTRAINT FK_ProduktInstanz_Lagerort
    FOREIGN KEY (LagerortId)
    REFERENCES Lagerorte(Id) ON DELETE SET NULL;

🔄 User Workflows

Workflow 1: Neuer Lagerort bei ProduktInstanz-Erstellung (UC10)

1. Benutzer öffnet "Produkt hinzufügen"
2. Füllt Lebensmittel, Menge, MHD aus
3. Gibt Lagerort ein: "lagerA"
4. System zeigt Auto-Complete: ["LagerA", "LagerB"]
5. Benutzer wählt "LagerA" ODER gibt neuen Namen "lagerC" ein
6. System normalisiert: "lagerC" → "LagerC"
7. System prüft: Existiert "LagerC" bereits?
   - Ja: Return existing Lagerort(Id=3)
   - Nein: Create new Lagerort(Name="LagerC") → Id=3
8. ProduktInstanz wird mit LagerortId=3 erstellt
9. Bestätigung: "Produkt zu Lager C hinzugefügt"

Workflow 2: Bestand zu anderem Lagerort buchen (UC2)

1. Benutzer öffnet "Lagerbestand aktualisieren"
2. Wählt Lebensmittel
3. Wählt "Zu anderen Lagerort buchen"
4. Gibt Lagerort ein: "lager2"
5. System zeigt Auto-Complete
6. Rest wie Workflow 1

Auto-Complete Fuzzy-Matching

Existierende Lagerorte: ["LagerA", "LagerB", "KuehlraumEins"]

Input: "lag" → Result: ["LagerA", "LagerB"]
Input: "kue" → Result: ["KuehlraumEins"]
Input: "xxx" → Result: [] (kein Match → neuer Lagerort möglich)
