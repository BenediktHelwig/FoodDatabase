UC2: Lagerbestand aktualisieren

Use-Case 2 | Status: ✅ COMPLETE

📋 Übersicht

Beschreibung: Benutzer kann Menge und Lagerort von Produktinstanzen aktualisieren. Dies ist zentral, um den aktuellen Bestand zu verwalten.

Hauptziele

  • Menge von Produktinstanzen ändern
  • Lagerort zuordnen (z.B. Kühlschrank, Vorratsschrank)
  • Sofortige Aktualisierung im System

Geschäftsnutzen

Der Benutzer kann seinen aktuellen Lagerbestand verwalten und jederzeit sehen, wie viel von welchem Produkt an welchem Ort vorhanden ist.

UC2-Operations auf ProduktInstanz

Hauptoperation: UpdateMengeAsync(id, newMenge)

Diese Operation aktualisiert die Menge einer ProduktInstanz:

// Vor Update
instanz.Menge = 500g

// UpdateMengeAsync(id=5, newMenge=300)
instanz.Menge = 300g  // GEÄNDERT

// Validierungen vor Update:
// ✓ newMenge > 0?
// ✓ id existiert?
// ✓ Keine Fehler → DB Update

🔄 User Workflows

Hauptworkflow: Bestand aktualisieren

1. Benutzer öffnet ProduktInstanz-Liste
2. Selektiert eine ProduktInstanz
3. Ändert Menge und/oder Lagerort
4. Klickt "Speichern"
5. System validiert Eingaben
6. System speichert Änderungen in DB
7. Benutzer sieht Erfolgsmeldung

Alternative Flows

Fehler: Ungültige Menge - System zeigt Validierungsfehler und verhindert Speichern

Lagerort nicht gefunden - System zeigt Dropdown mit verfügbaren Lagerorten

🔌 Service Interface (8 Methoden)

LagerbestandService-Methoden (ILagerbestandService)

1. GetGesamtmengeAsync(lebensmittelKatalogId: int)

Rückgabe: decimal

Beschreibung: Summiert die Menge aller ProduktInstanzen für ein Lebensmittel auf.

Test-Coverage: 4 Tests (valid ID, no instanzen, different IDs, null result)

var total = await service.GetGesamtmengeAsync(1); // z.B. 1000g

2. CheckMindestbestandUnterschrittenAsync(lebensmittelKatalogId: int)

Rückgabe: bool

Beschreibung: Prüft, ob die Gesamtmenge unter dem Mindestbestand liegt.

Test-Coverage: 4 Tests (under, above, equal, no instanzen)

bool isLow = await service.CheckMindestbestandUnterschrittenAsync(1); // true wenn < Mindestbestand

3. GetEinkaufslistenEintraegeAsync()

Rückgabe: List<ProduktInstanz>

Beschreibung: Gibt alle ProduktInstanzen zurück, deren Mindestbestand unterschritten ist.

Test-Coverage: 3 Tests (with unterschritten, without, empty repo)

var shopping = await service.GetEinkaufslistenEintraegeAsync(); // Nachbestellungen

4. GetBestaendePorLagerortAsync(lagerort: string)

Rückgabe: List<ProduktInstanz>

Beschreibung: Filtert ProduktInstanzen nach Lagerort (z.B. Kühlschrank, Vorratsschrank).

Test-Coverage: 3 Tests (valid location, empty, null lagerort)

var kühlschrank = await service.GetBestaendePorLagerortAsync("Kühlschrank");

5. AddToBestandAsync(lebensmittelKatalogId, menge, mindestbestandMenge, verfallsdatum, lagerort)

Rückgabe: ProduktInstanz

Beschreibung: Fügt neue Produktinstanz zum Bestand hinzu mit umfassender Validierung.

Validierungen: menge > 0, verfallsdatum >= today

Test-Coverage: 4 Tests (valid, negative menge, zero menge, past verfallsdatum)

var new_item = await service.AddToBestandAsync(1, 500m, 100m, DateTime.Today.AddDays(10), "Kühlschrank");

6. UpdateMengeAsync(id: int, newMenge: decimal) ⭐ HAUPTMETHODE UC2

Rückgabe: ProduktInstanz

Beschreibung: Aktualisiert die Menge einer existierenden ProduktInstanz. Dies ist die zentrale Methode für UC2.

Validierungen: newMenge > 0, id muss existieren

Test-Coverage: 4 Tests (valid data, negative menge, zero menge, non-existent id)

var updated = await service.UpdateMengeAsync(5, 300m); // Ändert Menge auf 300g

7. RemoveFromBestandAsync(id: int)

Rückgabe: void (Task)

Beschreibung: Löscht eine ProduktInstanz aus dem Bestand.

Test-Coverage: 3 Tests (valid id, non-existent id, verify delete called)

await service.RemoveFromBestandAsync(5); // Entfernt Instanz

8. ValidateBestandAsync(id: int, requiredMenge: decimal)

Rückgabe: bool

Beschreibung: Prüft, ob eine ProduktInstanz die geforderte Menge verfügbar hat (z.B. für Rezepte).

Test-Coverage: 4 Tests (valid, insufficient, equal, non-existent id)

bool has_enough = await service.ValidateBestandAsync(5, 100m); // true wenn Menge >= 100

Validierungsregeln (UC2)

UpdateMengeAsync-Validierungen:

  • Menge-Validierung: newMenge > 0 (nicht <= 0)
  • ID-Validierung: ProduktInstanz mit dieser ID muss existieren
  • Exception bei Fehler: ArgumentException oder KeyNotFoundException

AddToBestandAsync-Validierungen:

  • Menge: menge > 0
  • Verfallsdatum: verfallsdatum >= DateTime.Today (nicht in der Vergangenheit)
  • Lagerort: Wird als string übernommen, muss nicht null sein

CheckMindestbestandUnterschrittenAsync-Logik:

// Pseudocode
gesamtmenge = Sum(alle ProduktInstanzen für LebensmittelKatalogId)
mindestbestand = FirstOrDefault(ProduktInstanzen).MindestbestandMenge

if (gesamtmenge < mindestbestand) return true;  // Unterschritten!
else return false;                               // Okay

Sequence-Diagramme (UC2 Workflows)

Die folgenden Sequenz-Diagramme zeigen die drei Hauptszenarien für UC2 mit vollständiger Nachverfolgung der Interaktionen:

Szenario 1: Erfolgreiche Menge-Aktualisierung ✅ (Happy Path)

Akteure: Benutzer → UI → LagerbestandService → IRepository → SQLite-DB

  1. Benutzer klickt "Speichern" in UI mit id=5, newMenge=300g
  2. UI ruft UpdateMengeAsync(5, 300) auf
  3. Service-Validierung: newMenge > 0? ✓ PASS
  4. Service holt ProduktInstanz von Repository: GetByIdAsync(5)
  5. Repository gibt ProduktInstanz zurück (vorher: Menge=500g)
  6. Service aktualisiert in-memory: instanz.Menge = 300
  7. Service speichert: SaveAsync(instanz)
  8. Repository speichert in DB - Änderung erfolgreich ✓
  9. Service gibt aktualisierte ProduktInstanz zurück
  10. UI zeigt Erfolgsmeldung: "Menge aktualisiert: 300g" ✅

Resultat: DB enthält jetzt: Menge=300g, Benutzer bestätigt Erfolg

Szenario 2: Validierungsfehler (Ungültige Menge) ❌

Akteure: Benutzer → UI → LagerbestandService (Abbruch vor DB-Zugriff)

  1. Benutzer klickt "Speichern" mit id=5, newMenge=-100g (UNGÜLTIG!)
  2. UI ruft UpdateMengeAsync(5, -100) auf
  3. Service-Validierung: if (newMenge <= 0) → throw ArgumentException ❌
  4. Fehler wird zurückgeworfen mit Message: "Menge muss größer als 0 sein"
  5. UI fängt Exception und zeigt Validierungsfehler
  6. Benutzer sieht: "❌ Validierungsfehler: Menge muss > 0 sein"
  7. KEIN Repository/DB-Zugriff! - Fehler abgefangen vorher

Resultat: DB unverändert, Benutzer sieht klare Fehlermeldung

Szenario 3: Mindestbestand-Prüfung ⚠️ (Nachbestellungs-Warnung)

Akteure: UI → LagerbestandService → IRepository → SQLite-DB

  1. UI ruft CheckMindestbestandUnterschrittenAsync(lebensmittelId=7) auf
  2. Service holt alle ProduktInstanzen für dieses Lebensmittel: GetAllByLebensmittelIdAsync(7)
  3. Repository gibt 3 Instanzen zurück:
    • Instanz 1: Menge=15g, Lagerort="Kühlschrank"
    • Instanz 2: Menge=20g, Lagerort="Vorratsschrank"
    • Instanz 3: Menge=10g, Lagerort="Gefrierfach"
  4. Service-Berechnung: Gesamtmenge = 15 + 20 + 10 = 45g
  5. Service prüft: 45 < 100 (MindestbestandMenge)? → TRUE ⚠️
  6. Service gibt true zurück (Mindestbestand UNTERSCHRITTEN)
  7. UI zeigt Warnung: "⚠️ Mindestbestand unterschritten! Aktuell 45g, Ziel: 100g. Bitte nachbestellen."
  8. Optional: Automatischer Eintrag in Einkaufsliste (UC8)

Resultat: Benutzer wird proaktiv informiert, dass Nachbestellungen nötig sind
