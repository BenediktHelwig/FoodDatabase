UI-Shell-Layout ✅ FERTIG

Überblick

Die UI-Shell-Layout-Fix implementiert eine responsive Navigationsstruktur basierend auf Bootstrap 5.3.3. Sie ersetzt den vorherigen Layout-Bug (`.page`-Selektor fehlte) und den 4-KB-CSS-Stub durch echtes Bootstrap.

Problem vorher: Seiteninhalte erschienen erst nach vollständigem Scrollen nach unten.
Root-Cause: CSS-Selektor `page` statt `.page` in der Media-Query (Zeile 86 alt).

🏗️ Architektur-Komponenten

Blazor-Komponentenbaum


App.razor (root HTML + Bootstrap 5.3.3 CSS/JS)
  ├─ Routes.razor (Router)
  │   └─ MainLayout.razor (Seiten-Layout)
  │       ├─ NavMenu.razor (responsive Off-Canvas Navigation)
  │       │   └─ <nav class="navbar navbar-expand-md">
  │       │       ├─ navbar-brand (Desktop + Mobile)
  │       │       ├─ navbar-toggler (nur Mobile, < 768px)
  │       │       └─ offcanvas offcanvas-start (Navigation Panel)
  │       │           └─ 7 NavLinks (Start, Lebensmittel, Lagerbestand, Lagerorte, Rezepte, Warnungen, Einkaufsliste)
  │       └─ main (Inhaltsbereich)
  │           └─ article.content (@Body)

📱 Responsives Verhalten (Breakpoint 768px)

Bildschirmgröße Navigation Layout Verhalten
< 768px (Mobil) Menü-Button oben links sichtbar Vertikal (.page { flex-direction: column }) Button öffnet Off-Canvas-Panel von links; Panel hat position: fixed; Klick auf Link schließt Panel; ESC schließt Panel
≥ 768px (Desktop) Feste Sidebar links, alle 7 Links sichtbar Horizontal (.page { flex-direction: row }) Kein Menü-Button; Sidebar bleibt oben beim Scrollen (position: sticky)

🎨 Styling-Änderungen

CSS-Datei (app.css)

  • .page: Basis-Flexbox-Container (flex-direction: column)
  • main: flex: 1 (nimmt restlichen Platz ein)
  • .sidebar: Farbverlauf (dunkelblau → violett); unter Desktop fixed nicht sichtbar
  • #navbarOffcanvas: Gleicher Farbverlauf (erforderlich für fixed Panel mobil)
  • @media (min-width: 768px):
    • .page → flex-direction: row
    • .sidebar → width: 250px; height: 100vh; position: sticky
