UC6: Verbrauch ausbuchen

Use-Case 6 | Status: ✅ FERTIG

📋 Übersicht

Beschreibung: Bucht eine verbrauchte Packung aus dem Lagerbestand aus. Das System verwendet das FIFO-Prinzip (First-In-First-Out) nach Verfallsdatum.

Hauptziele

  • Ganze Packung aus dem Bestand entfernen (Delete)
  • FIFO-Reihenfolge nach Verfallsdatum (älteste zuerst)
  • Fehlerbehandlung wenn keine Packung vorhanden

Geschäftsnutzen

Der Benutzer kann verbrauchte Lebensmittel registrieren. Das System removes automatisch die älteste Packung nach MHD, um Verschwendung durch Verfall zu vermeiden.

📦 Domain Model

Beteiligte Entities & Services

Komponente Rolle Beziehung
IVerbrauchAusbuchangService Service-Interface Definiert VerbauchtProduktAsync(lebensmittelId)
VerbrauchAusbuchangService Service-Implementierung Implementiert FIFO-Logik
ProduktInstanz Zu löschende Packung Wird komplett gelöscht (nicht reduziert)
ServiceResult Return-Type Success: bool, Message: string

Aktion (FIFO-Logik)

Verbrauch ausbuchen:
  Input: LebensmittelKatalogId
  1. Validierung: lebensmittelKatalogId > 0?
  2. Filter: Alle ProduktInstanzen nach LebensmittelId
  3. Sortierung: Nach Verfallsdatum (ascending = älteste zuerst)
  4. Aktion: Älteste ProduktInstanz komplett löschen
  5. Result: ServiceResult(Success=true, Message="Produkt erfolgreich verbraucht")

🔄 User Workflows

Workflow (Happy Path)

1. Benutzer öffnet "Verbrauch ausbuchen"
2. Wählt Lebensmittel (z.B. "Mehl" mit ID 5)
3. Klickt "Ausbuchen"
4. System findet älteste Packung (nach MHD)
5. System löscht die Packung
6. Bestätigung: "Produkt erfolgreich verbraucht"

Fehlerfall 1: Keine Packung vorhanden

1. Benutzer wählt Lebensmittel "Zucker" (keine Packung im Bestand)
2. System sucht nach ProduktInstanzen
3. Keine gefunden → ServiceResult(false, "...")
4. Fehlermeldung: "Produkt nicht vorhanden"

Fehlerfall 2: Ungültige Eingabe

1. Benutzer gibt LebensmittelId <= 0 ein
2. System wirft ArgumentException
3. Validierungsfehler

FIFO-Verhalten

Wenn mehrere Packungen im Bestand sind, wird die mit dem frühesten Verfallsdatum gelöscht (älteste zuerst). Dies verhindert unnötige Verschwendung.

🔌 Service Interface

Service-Interface

public interface IVerbrauchAusbuchangService
{
    /// <summary>
    /// Bucht die älteste ProduktInstanz (nach Verfallsdatum) aus.
    /// </summary>
    Task<ServiceResult> VerbauchtProduktAsync(int lebensmittelKatalogId);
}

Service-Implementierung (Highlights)

1. Validierung: lebensmittelKatalogId > 0 (throw ArgumentException wenn nicht)
2. GetAllAsync(): Alle ProduktInstanzen abrufen
3. Filter: Where(x => x.LebensmittelKatalogId == lebensmittelKatalogId)
4. Sort: OrderBy(x => x.Verfallsdatum).First() (FIFO = älteste zuerst)
5. Delete: DeleteAsync(aeltesteInstanz.Id)
6. Return: ServiceResult(true/false, Message)

📝 Notizen & Besonderheiten

Implementierungs-Highlights

  • FIFO-Prinzip: Älteste Packung (nach MHD) wird zuerst verbraucht → Minimierung von Verschwendung
  • Ganze Packungen: Keine Gramm-genaue Ausbuchung, sondern komplette Packung-Löschung
  • ServiceResult Pattern: Bessere Fehlerbehandlung mit Success-Flag + Message (statt Exceptions für normale Fehler)
  • TDD-Ansatz: 10 Unit-Tests vor Code → 100% Test-Coverage

Future Enhancements

  • Barcode-Scanning zum schnelleren Verbrauch
  • Verbrauchshistorie / Audit-Log
  • Batch-Verbrauch (mehrere Packungen gleichzeitig)
  • Verfallsdatum-Warnungen vor Verbrauch (UC7 Integration)

Designentscheidungen

Warum ganze Packungen statt Gramm-weise? Lebensmittel werden in definierten Packungsgrößen verkauft und eingekauft. Gramm-weise Ausbuchung ist in dieser Lösung komplex und unötig – eine Packung ist eine Einheit.

Warum ServiceResult statt Exception? Fehler wie "Produkt nicht vorhanden" sind erwartete Geschäftsfälle, keine außergewöhnliche Umstände. ServiceResult ermöglicht bessere UI-Fehlerbehandlung.
