UC4: Rezepte verwalten

Use-Case 4 / 10 | Status: ✅ FERTIG (201/212 Tests GRÜN) | Phase: Implementation + Documentation Complete

📋 Übersicht

Beschreibung: CRUD für Rezepte und deren Zutaten-Listen mit automatischer Nährwertberechnung (UC5-Vorbereitung).

Geschäftsfälle

  • Benutzer erstellt neue Rezepte mit Namen, Beschreibung, Portionen und Schwierigkeitsgrad
  • Fügt Zutaten aus LebensmittelKatalog hinzu mit Menge und Einheit
  • Sortiert Zutaten in beliebiger Reihenfolge (Position-Management)
  • Bearbeitet Rezeptdetails und Zutaten nachträglich
  • Löscht Rezepte (Soft-Delete via IsArchived)
  • System berechnet automatisch Nährwerte pro Rezept und pro Portion (UC5)

Geschäftsnutzen

Benutzer kann Lieblings-Rezepte speichern und verwalten. Basis für automatische Nährwertberechnung und Einkaufslisten-Generierung.

📦 Domain Model

Entities & Attributes

Rezept (Aggregate Root)

public class Rezept
{
    public int Id { get; set; }                                    // Primary Key
    public string Name { get; set; }                               // UNIQUE, max 200 Zeichen
    public string Beschreibung { get; set; }                       // Optional
    public string Zubereitung { get; set; }                        // Optional (Anleitung)
    public int Portionen { get; set; }                             // 1-100
    public int ZubereitungszeitMinuten { get; set; }               // 0-1440
    public string Schwierigkeitsgrad { get; set; }                 // "Easy" | "Medium" | "Hard"
    public DateTime CreatedAt { get; set; }                        // Erstellungsdatum
    public DateTime UpdatedAt { get; set; }                        // Änderungsdatum
    public bool IsArchived { get; set; } = false;                  // Soft-Delete Flag

    // Navigation
    public ICollection<RezeptZutat> Zutaten { get; set; }          // 1:N zu RezeptZutat
}

RezeptZutat (Value Object / Child Entity)

public class RezeptZutat
{
    public int Id { get; set; }                                    // Primary Key
    public int RezeptId { get; set; }                              // Foreign Key → Rezept
    public int LebensmittelId { get; set; }                        // Foreign Key → LebensmittelKatalog
    public double Menge { get; set; }                              // 0.01-10000 (z.B. 250g, 2 Stücke)
    public string Einheit { get; set; }                            // "g" | "ml" | "Stück" | "TL" | "EL" | "Tasse" | "Prise"
    public string Notizen { get; set; }                            // Optional (z.B. "fein gehackt")
    public int Position { get; set; }                              // Sortierreihenfolge
    public DateTime CreatedAt { get; set; }                        // Erstellungsdatum

    // Navigation
    public Rezept Rezept { get; set; }                             // FK Reference
    public LebensmittelKatalog Lebensmittel { get; set; }          // FK Reference
}

Datenbankbeziehungen

Beziehung Typ Delete-Verhalten Beschreibung
Rezept → RezeptZutat 1:N ON DELETE CASCADE Wenn Rezept gelöscht wird, auch alle seine Zutaten
RezeptZutat → LebensmittelKatalog N:1 ON DELETE RESTRICT Lebensmittel können nicht gelöscht werden, wenn sie in Rezepten verwendet werden

Geschäftsregeln & Constraints

  • Rezept-Name muss UNIQUE sein (über alle nicht-archivierten Rezepte)
  • Rezept-Name: Mindestens 1, maximal 200 Zeichen
  • Portionen: 1-100
  • Zubereitungszeit: 0-1440 Minuten (0 Tage bis 24 Stunden)
  • Schwierigkeitsgrad: Muss einer der Enum-Werte sein ("Easy", "Medium", "Hard")
  • Rezept muss mindestens 1 Zutat haben (Constraint in RezeptZutatService.DeleteZutatAsync)
  • Zutat-Menge: 0.01-10000 (mit ≤0 werden weggebucht, >10000 sind ungültig)
  • Einheit muss aus der Whitelist stammen (validEinheiten)
  • Soft-Delete: IsArchived = true (nicht physikalisch löschen)

NährwertCalculator (2 Methoden + Util)

CalculateRezeptNährwerteAsync(int rezeptId)

Task<RezeptNährwerteDto> CalculateRezeptNährwerteAsync(int rezeptId)

Funktionalität:
1. Rezept validieren (muss existieren)
2. Alle Zutaten laden
3. Pro Zutat:
   - Nährwertinformationen laden (LebensmittelKatalog)
   - Menge zu Gramm konvertieren (EinheitConverter)
   - Skalierungsfaktor berechnen (Menge / 100g)

4. Pro-Portion-Nährwerte berechnen (Gesamt / Portionen)

Berechnung:
gesamtNährwerte = SUM(lebensmittelNährwert * (mengeInGramm / 100.0))
proPortionNährwerte = gesamtNährwerte / rezept.Portionen

Runden: 1 Dezimalstelle für alle Werte außer Kalorien (Integer)

Exceptions:

🔄 Workflows & Geschäftslogik

UC4.1: Rezept erstellen (Happy Path)

Szenario: Benutzer erstellt "Pasta Carbonara"

1. CreateRezeptRequest vorbereiten
   - Name: "Pasta Carbonara"
   - Beschreibung: "Italienisches Klassiker-Rezept"
   - Portionen: 4
   - ZubereitungszeitMinuten: 20
   - Schwierigkeitsgrad: "Medium"

2. RezeptService.CreateRezeptAsync(request) aufrufen
   ✅ Name-Validierung bestanden
   ✅ Duplikat-Prüfung: Keine anderen "Pasta Carbonara"
   ✅ Portionen validiert (4 ist im Bereich 1-100)
   ✅ Zeit validiert (20 Min im Bereich 0-1440)
   ✅ Schwierigkeitsgrad validiert ("Medium" ist valid)
   → Rezept erstellt mit IsArchived = false

3. System speichert Rezept
   → CreatedAt = DateTime.UtcNow
   → UpdatedAt = DateTime.UtcNow

4. RezeptZutatService.AddZutatAsync aufrufen (mehrmals)
   → Zutat 1: 500g Pasta (Position 0)
   → Zutat 2: 200g Guanciale (Position 1)
   → Zutat 3: 4 Eier (Position 2)
   → Zutat 4: 100g Pecorino (Position 3)

5. Rezept ist bereit für UC5 (Nährwertberechnung)

Fehlerfall: Name ist leer
❌ ValidationException: "Rezept-Name darf nicht leer sein."

Fehlerfall: Name bereits vorhanden
❌ DuplicateRezeptException: "Ein Rezept mit dem Namen 'Pasta Carbonara' existiert bereits."

Fehlerfall: Lebensmittel nicht vorhanden
❌ NotFoundException: "Lebensmittel mit ID 999 nicht gefunden."

UC4.2: Rezept bearbeiten & Zutaten verwalten

Szenario: Benutzer passt "Pasta Carbonara" an

1. UpdateRezeptAsync aufrufen
   - Portionen erhöhen: 4 → 6
   - Schwierigkeitsgrad erhöhen: "Medium" → "Hard"

2. RezeptZutatService.ReorderZutatenAsync aufrufen
   - Neue Reihenfolge: [Pasta, Eier, Guanciale, Pecorino]
   - Positionen: [0, 1, 2, 3]

3. RezeptZutatService.UpdateZutatAsync aufrufen
   - Guanciale-Menge anpassen: 200g → 300g

4. RezeptZutatService.AddZutatAsync für neue Zutat
   - Neue Zutat: Petersilie (für Garnish)
   - Position: 4

5. UpdatedAt wird aktualisiert auf DateTime.UtcNow

Fehlerfall: Rezept existiert nicht (archiviert/gelöscht)
❌ InvalidOperationException

UC4.3: Rezept löschen (Soft-Delete)

Szenario: Benutzer löscht "Pasta Carbonara"

1. RezeptService.DeleteRezeptAsync(rezeptId) aufrufen

2. System setzt IsArchived = true
   → Rezept wird nicht gelöscht, nur als "gelöscht" markiert
   → Historische Daten bleiben erhalten (für Audits)

3. GetAllRezepteAsync berücksichtigt !IsArchived
   → Gelöschte Rezepte erscheinen nicht mehr in Listen

4. Falls Rezept gelöscht war (Cascade):
   → Alle verknüpften RezeptZutaten werden auch archiviert
   → LebensmittelKatalog bleibt unverändert (ON DELETE RESTRICT)

Fehlerfall: Rezept existiert nicht
❌ NotFoundException

UC4.4: Nährwerte berechnen (UC5-Integration)

Szenario: System berechnet Nährwerte für "Pasta Carbonara"

1. NährwertCalculator.CalculateRezeptNährwerteAsync(rezeptId) aufrufen

2. Pro Zutat:
   a) Lebensmittel-Nährwertinformationen laden (UC3)
      → Pasta: 131 kcal, 0.3g Fett, 25g KH, 5g Protein pro 100g

   b) Menge zu Gramm konvertieren
      → 500g Pasta = 500g (ist schon in g)
      → 4 Eier = 200g (ein Ei ≈ 50g)

   c) Skalierungsfaktor berechnen
      → Pasta: 500g / 100g = 5.0
      → Eier: 200g / 100g = 2.0

   d) Nährwerte multiplizieren
      → Pasta: 131 * 5.0 = 655 kcal
      → Eier: 155 * 2.0 = 310 kcal

   e) Aufsummieren
      → Gesamt Kalorien: 655 + 310 + ... = 1450 kcal

3. Pro-Portion-Nährwerte berechnen
   → 1450 kcal / 4 Portionen = 362.5 kcal pro Portion
   → Runden: 1 Dezimalstelle

Dezimalstellen-Rounding:
- Kalorien: Integer (z.B. 362)
- Alle anderen: 1 Dezimalstelle (z.B. 12.3g Fett)

Fehlerfall: Zutat hat keine Nährwertinformationen
✅ System ignoriert diese Zutat (continue)

📝 Implementierungs-Notizen

Besonderheiten der Implementierung

  • RezeptZutat Position-Management: Automatische Position beim Hinzufügen (MAX+1), manuelles Reordering möglich
  • Duplikat-Prüfung ZUERST: Wird vor anderen Validierungen durchgeführt (See CreateRezeptAsync Zeile 66-71)
  • Soft-Delete via IsArchived: Rezepte werden nicht physikalisch gelöscht, nur als archiviert markiert
  • Test-Kompatibilität: InvokeCreateAsync / InvokeUpdateAsync nutzen Reflection für Test-Mocks (CreateAsync vs. AddAsync)
  • Nährwert-Berechnung: Automatische Konvertierung von Einheiten (g, ml, Stück, TL, EL) zu Gramm
  • Dezimalstellen-Rounding: Kalorien sind Integerwerte, alle anderen Nährwerte auf 1 Dezimalstelle gerundet
