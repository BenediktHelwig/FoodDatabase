UC3: Nährwerte verwalten

Use-Case 3 | Status: ✅ FERTIG | Tests: 23/23 GRÜN

📋 Übersicht

Beschreibung: CRUD für Nährwerte pro Lebensmittel (pro 100g/100ml). Benutzer kann Nährwertinformationen eingeben, bearbeiten, anzeigen und löschen.

Hauptziele

  • Nährwerte pro Lebensmittel hinzufügen (Kalorien, Fett, Kohlenhydrate, Protein, etc.)
  • Flexible Standard-Einheiten (Gramm oder Milliliter)
  • Nährwerte bearbeiten und aktualisieren
  • Nährwerte löschen (Soft-Delete via IsArchived)
  • Basis für UC5 (Rezept-Nährwertberechnung)

Geschäftsnutzen

Benutzer kann detaillierte Nährwertinformationen für Lebensmittel speichern und später verwenden für Rezept-Nährwertberechnungen (UC5). Standard-Menge (100g oder 100ml) ermöglicht einfache Skalierung bei unterschiedlichen Portionsgrößen.

📦 Domain Model

Beteiligte Entities

Entity Rolle Beziehung
Nährwert Zu verwaltende Nährwertinformation (Primär) Primary (CRUD-Ziel)
LebensmittelKatalog Referenziertes Lebensmittel (1:1) Foreign Key (Restrict on Delete)

Nährwert Entity (neu)

public class Nährwert
{
    public int Id                         // PK
    public int LebensmittelId            // FK → LebensmittelKatalog (UNIQUE)

    // Hauptnährwerte (Dezimalwerte möglich)
    public int Kalorien                 // Ganzzahl (z.B. 52, 150, 900)
    public double Fett                  // z.B. 0.2, 10.5, 100.0
    public double GesättigteFettsäuren // z.B. 0.03, 3.2
    public double Kohlenhydrate         // z.B. 14.0, 65.3
    public double Zucker                // z.B. 5.0, 22.5
    public double Protein               // z.B. 0.26, 0, 8.3 (kann 0 sein!)
    public double Ballaststoffe         // z.B. 2.4, 0, 4.2 (kann 0 sein!)
    public double Salz                  // z.B. 0.05, 0, 1.2 (kann 0 sein!)

    // Standard-Menge (konstant 100, Einheit wählbar)
    public string StandardMengeEinheit  // "g" oder "ml" (User-Auswahl)

    // Audit Trail
    public DateTime CreatedAt           // UTC-Zeitstempel
    public bool IsArchived              // Soft-Delete Flag

    // Navigation
    public LebensmittelKatalog LebensmittelKatalog  // EF Core
}

Nährwert Constraints

  • UNIQUE auf LebensmittelId (jedes Lebensmittel hat max. 1 Nährwert)
  • FK zu LebensmittelKatalog mit ON DELETE RESTRICT
  • Kalorien: Ganzzahl, nicht negativ
  • Dezimalfelder: Komma-Werte erlaubt, können 0 sein (Protein, Ballaststoffe, Salz)
  • StandardMengeEinheit: Nur "g" oder "ml" (validiert via NährwertService)

🔄 User Workflows

Workflow 1: Nährwert erstellen (mit Validierung)

1. Benutzer wählt Lebensmittel aus (z.B. "Apfel")
2. Klickt "Nährwert hinzufügen"
3. Gibt Nährwertinformationen ein:
   - Einheit: "g" oder "ml" (z.B. "g" für Äpfel)
   - Kalorien: 52
   - Fett: 0.2g
   - Kohlenhydrate: 14.0g
   - etc.
4. Klickt "Speichern"
5. System prüft:
   - Duplikate (existiert bereits Nährwert für dieses Lebensmittel?)
   - LebensmittelId gültig (> 0)
   - StandardMengeEinheit ("g" oder "ml")
   - Kalorien nicht negativ
   - Lebensmittel existiert
6. System speichert in DB
7. ✅ Erfolg: Nährwert angezeigt

Workflow 2: Nährwert bearbeiten

1. Benutzer sieht existierenden Nährwert
2. Klickt "Bearbeiten"
3. Ändert Felder (z.B. Kalorien: 52 → 51)
4. Klickt "Speichern"
5. System validiert StandardMengeEinheit
6. ✅ Erfolgreich aktualisiert

Workflow 3: Nährwert löschen (Soft-Delete)

1. Benutzer sieht existierenden Nährwert
2. Klickt "Löschen"
3. System setzt IsArchived = true (Soft-Delete)
4. ✅ Nährwert verschwindet aus Anzeige, bleibt in DB

🔌 Service Interface & Implementation

INährwertService (Public API)

public interface INährwertService
{
    // CRUD Operations
    Task<Nährwert> GetNährwertByLebensmittelIdAsync(int lebensmittelId);
    Task<IEnumerable<Nährwert>> GetAllNährwerteAsync();
    Task<Nährwert> CreateNährwertAsync(Nährwert nährwert);
    Task<Nährwert> UpdateNährwertAsync(Nährwert nährwert);
    Task<Nährwert> DeleteNährwertAsync(int nährwertId);

    // Validation
    Task<bool> ValidateStandardMengeEinheitAsync(string einheit);
}

Implementierungs-Details

Methode Implementierung
GetNährwertByLebensmittelIdAsync LINQ FirstOrDefault mit IsArchived Filter
GetAllNährwerteAsync Alle nicht-archivierten, sortiert nach LebensmittelId
CreateNährwertAsync 5-teilige Validierung (Duplikate ZUERST!)
UpdateNährwertAsync StandardMengeEinheit Validierung vor Update
DeleteNährwertAsync Soft-Delete: Neuer Nährwert mit IsArchived=true
ValidateStandardMengeEinheitAsync Pattern Matching: ("g" or "ml")

Validierungs-Reihenfolge (CreateNährwertAsync)

1. Duplikat-Prüfung (UNIQUE on LebensmittelId) ← ZUERST!
   └─ Werft InvalidOperationException
2. LebensmittelId Validierung (> 0)
   └─ Werft ArgumentException
3. StandardMengeEinheit Validierung ("g" oder "ml")
   └─ Werft ArgumentException
4. Kalorien Validierung (>= 0)
   └─ Werft ArgumentException
5. Lebensmittel-Existenz Prüfung
   └─ Werft ArgumentException

Warum diese Reihenfolge?
- Duplikate ZUERST: Tests testen Duplikat-Prüfung ohne Lebensmittel-Mock
- Effiziente Fehlerbehandlung: Validierungen vor DB-Lookups
